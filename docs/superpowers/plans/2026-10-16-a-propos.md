# Page /a-propos — plan de réalisation

> **Pour l'exécutant :** exécuté par Claude dans la session de conception (choix d'Augustin), tâche par tâche,
> avec superpowers:executing-plans. Cases à cocher (`- [ ]`) pour le suivi.

**But :** publier `/a-propos`, qui montre trois projets d'école (vidéo ou graphiques d'abord, puis « Ma part »),
les deux projets freelance en cartes, puis le parcours détaillé en frise verticale.

**Architecture :** contenus dans `data/a-propos.ts` ; page serveur `app/a-propos/page.tsx` faite de composants
serveur (`components/a-propos/`), sauf `VideoProjet`, seul composant client (lecture à l'écran, pause hors
écran). Médias tournés par Claude sur des copies des projets, rangés dans `public/a-propos/`, plafonnés par un
contrôle de taille en CI.

**Technique :** Next 16 (App Router), React 19, Tailwind v4, Vitest + Testing Library, Playwright, ffmpeg
(SVT-AV1, x264), Docker Compose pour lancer les projets filmés.

**Spec :** `docs/superpowers/specs/2026-10-16-a-propos-design.md`

## Contraintes globales

- Branche `a-propos` (déjà créée depuis `origin/main`, spec commitée). Commits ciblés, messages en français,
  sans ligne d'attribution. Jamais de `--force`, de `reset --hard` ni de `git stash` nu.
- Ne jamais écrire dans `~/Documents/Projets/epitech/` : copies dans le dossier temporaire de la session
  (`$S` = scratchpad), sans `.git`, `node_modules`, `.venv`.
- Lire le guide concerné dans `apps/web/node_modules/next/dist/docs/` avant le code Next (métadonnées,
  `opengraph-image`, `next/image`).
- Conventions de mise en page : `mx-auto w-full max-w-6xl 2xl:max-w-page px-5 sm:px-8` ; surtitres
  `text-xs font-medium uppercase tracking-[0.14em] text-texte-doux` ; titres en `font-serif`.
- Ton factuel, aucun mot de candidat (« Open to work », « recherche », « disponible »). Aucun nom de
  coéquipier, aucune donnée réelle, rien d'interne à SCR.
- Accueil : aucun JavaScript ajouté ; lien vers `/a-propos` avec `LienAuSurvol` (préchargement à l'intention
  seulement, comme l'accroche) ; `verifier-accueil-statique` reste vert.
- Mouvement réduit : aucune vidéo ne démarre seule.
- Tests : Vitest `--reporter=dot`, Playwright `--reporter=line`, sorties longues redirigées dans `$S`.
  e2e local : `docker start jouandev-postgres-1`, puis
  `export $(grep -E '^DATABASE_URL=' .env.local | xargs) && PLAYWRIGHT_BROWSERS_PATH=$HOME/.cache/ms-playwright pnpm exec playwright test …`
  après `pnpm build`. Ne jamais afficher `.env.local` ; ne pas tuer le `next dev` du port 3000.

## Points de vigilance (non couverts par la spec, testés dans la tâche indiquée)

1. Téléphone de 360 px : avec « À propos », le menu du haut ne déborde pas et tient sur une ligne → tâche 5.
2. Mouvement réduit : une vidéo visible reste en pause, et peut être lancée à la main → tâche 3 (unitaire) et
   tâche 6 (e2e).
3. Navigateur sans AV1 (Safari ancien) : la vidéo passe par la source MP4 → tâche 3 (deux `<source>` typées,
   WebM AV1 d'abord).
4. Vidéo sortie de l'écran : elle se met en pause (batterie, processeur) → tâche 3.
5. Lien d'une carte freelance : il ouvre `/realisations` sur le bon onglet, à la bonne étude → tâche 6.

### Tâche 3 : le lecteur vidéo

**Fichiers :**
- Créer : `components/a-propos/VideoProjet.tsx` (`"use client"`), `VideoProjet.test.tsx`.

**Interfaces :**
- Consomme : `VideoProjet` (type, tâche 2) — importer le type sous un autre nom (`type VideoProjet as Video`).
- Produit : `export function VideoProjet({ video }: { video: Video }): JSX.Element`.

Comportement : `<video muted loop playsInline preload="none" poster width height aria-label={description}>`
avec deux `<source>` : WebM `type='video/webm; codecs="av01.0.08M.08"'` puis MP4 `type="video/mp4"`. Un
`IntersectionObserver` (seuil 0,25) lance `play()` quand la vidéo est visible et `pause()` quand elle sort, sauf
si `matchMedia("(prefers-reduced-motion: reduce)")` est vrai : alors aucun `play()` automatique et la vidéo
reçoit `controls`. Sans `IntersectionObserver` : pas de lecture automatique, `controls`. Coins et bordure comme
`FenetreDemo` (`rounded-3xl border border-trait bg-surface`).

- [ ] **Étape 1 : tests** (observateur et `matchMedia` factices, comme `FenetreDemo.test.tsx` ;
  `HTMLMediaElement.prototype.play/pause` espionnés) :
  - « visible : lit la vidéo ; hors écran : la met en pause » ;
  - « mouvement réduit : jamais de lecture automatique, et des contrôles pour la lancer » ;
  - « deux sources, WebM AV1 d'abord puis MP4, avec leur type » ;
  - « affiche et dimensions posées dès le rendu (pas de décalage), `preload="none"`, nom accessible = description ».
- [ ] **Étape 2 : lancer** → échec. **Étape 3 : implémenter.** **Étape 4 : relancer** → PASS.
- [ ] **Étape 5 : commit** « /a-propos : lecteur vidéo (lecture à l'écran, pause hors écran, mouvement réduit) ».
